# 비밀동네 — 위치 기반 탐정·탐험·소셜 게임 기획서

> **걸을수록 비밀이 드러나고, 내가 남긴 이야기가 다른 사람의 모험이 된다.**

- 문서 버전: v0.2
- 작성일: 2026-09-30
- 상태: 웹 사건 체험 및 1인칭 AR 콘셉트 프로토타입 구현. 실제 공간 추적·실기기 검증 전.
- 프로젝트명: **비밀동네** — 가칭. 영문명·브랜드·상표는 미정.
- 검토 플랫폼: Meta Ray-Ban Display의 HUD 경로와 공간 앵커 지원 AR 플랫폼을 분리 검토
- 현재 개발 환경: 카운터 웹앱, 스마트폰 사건 체험, 가상 동네 AR 콘셉트 시뮬레이션

## 방향 수정 — 공간에 보이는 단서와 길 안내

사용자의 핵심 의도는 텍스트 사건을 읽는 것을 넘어, **글래스를 통해 단서가 실제 장소에 떠 있고 퀘스트 경로가 눈앞에 보이는 경험**이다. 이를 제품의 목표 경험에 포함한다. 아래 초기 MVP의 텍스트 중심 범위는 첫 검증용으로 유지하되 최종 경험을 제한하는 결정으로 해석하지 않는다.

- **목표 경험:** 장소에 떠 있는 단서, 접근에 따른 거리 변화, 이동 방향 안내, 가능하다면 바닥과 정렬된 경로.
- **이미 만든 것:** `prototype/ar.html`의 가상 3D 동네, 시점 회전·이동, 바닥 경로·봉투 표시, 4m 이내 조사, 세 단서와 결말. 실제 세계가 아닌 내부 가상 좌표에 고정된다.
- **Meta Display 검토:** 공식 웹앱 문서는 위치·방향 센서와 600×600 투과형 디스플레이를 안내한다. 화면 내 방향·거리 HUD를 검토할 수 있지만, 실제 벤치나 도로에 안정적으로 고정하는 공간 앵커 API는 이번에 확인한 문서에서 확인하지 못했다.
- **플랫폼 결정 조건:** 고정된 공간 단서가 필수이면 공간 추적·앵커가 지원되는 AR 플랫폼도 비교한다. 단순 GPS·방향 센서 조합을 정밀한 공간 추적으로 간주하지 않는다.
- **시뮬레이션의 한계:** 브라우저에서 가상 공간 연출이 성공해도 실제 기기의 추적·정렬·가림·지연·시야각을 검증한 것은 아니다.

근거: [Meta 웹앱 기능](https://developers.meta.com/wearables/web-apps/), [Snap Spatial Anchors](https://developers.snap.com/spectacles/about-spectacles-features/apis/spatial-anchors), [Snap Navigation Kit](https://developers.snap.com/spectacles/spectacles-frameworks/spectacles-navigation-kit/getting-started).

## 1. 기획의 목적

사람들이 “이 앱을 쓰려고 글래스를 사고 싶다”고 느낄 경험을 만든다.

비밀동네는 실제 동네의 공공장소를 무대로 가상의 사건을 해결하는 게임이다. 사건을 따라 걸으면 나만의 탐험 기록이 쌓이고, 친구 또는 미래의 자신에게 남긴 메시지가 그 장소의 다음 이야기가 된다.

지도는 화면에 오래 띄워두는 콘텐츠가 아니라 **사건의 장소, 이동 경로, 도착 조건을 만드는 기반**으로 사용한다. 글래스는 주변 풍경과 사람을 계속 보면서 짧은 단서와 안내를 받는 도구다.

### 제품 가설

1. 짧은 사건은 평범한 산책과 퇴근길에 새로운 동기를 준다.
2. 탐험 기록과 수집품은 일회성 체험을 반복 사용으로 연결한다.
3. 친구와 함께 푼 사건과 장소에 남긴 편지는 개인적인 애착을 만든다.
4. 걷기와 대화를 방해하지 않는 글래스 경험은 스마트폰 경험보다 선호될 수 있다.

**네 번째 가설은 아직 검증되지 않았다.** 게임이 재미있다는 사실만으로 글래스 구매 동기가 증명되지는 않는다.

## 2. 합의한 방향과 미정 사항

| 구분 | 내용 |
|---|---|
| 합의한 콘셉트 | 탐정 놀이, 동네 탐험·수집, 친구의 흔적을 하나의 경험으로 결합 |
| 경험 원칙 | 혼자서도 시작할 수 있고, 친구가 참여하면 더 재미있게 만들기 |
| 첫 검증 방향 | 동네 한 곳에서 짧은 사건 하나를 처음부터 끝까지 체험 |
| 기획 제안 | 첫 사건 15분, 조사 장소 3곳, 추리 선택 3회, 수집품 1개 |
| 아직 미정 | 실제 대상 동네, 최종 사건 대본, 지도 공급자, 기술 구성, 과금, 출시 일정 |
| 별도 검증 필요 | 실기기 입력·위치·오디오·백그라운드 동작, 배포 및 계정 접근 조건 |

이 문서의 시간·거리·수량·검증 기준은 초기 설계 목표이며 측정 결과가 아니다.

## 3. 초기 사용자와 사용 상황

### 우선 사용자

- 평소 산책을 하지만 같은 코스가 지루한 사람
- 방탈출·추리·스토리 게임을 좋아하는 사람
- 친구나 연인과 짧고 가벼운 야외 활동을 원하는 사람

처음부터 여행객, 가족, 기업 행사까지 동시에 만족시키려 하지 않는다. **익숙한 동네에서 15~25분 정도 새로운 경험을 원하는 성인 사용자**를 우선 검증한다.

### 시작 모드

| 모드 | 제안 시간 | 경로 | 목적 |
|---|---:|---|---|
| 가는 길에 | 추가 10분 안팎 | 목적지까지 허용 범위 내 우회 | 퇴근·약속 이동 중 짧은 사건 |
| 한 바퀴 | 약 25분 | 출발점으로 복귀 | 혼자 하는 산책과 탐험 |
| 같이 놀기 | 약 40분 | 함께 이동하는 코스 | 서로 다른 단서를 맞추는 협동 |

세 모드는 장기 제품 방향이다. MVP에서는 사전 답사한 **고정 코스 한 개**만 제공한다.

## 4. 핵심 경험 구조

### 세 요소의 역할

| 요소 | 역할 | 사용자에게 남는 것 |
|---|---|---|
| 사건 해결 | 오늘 밖에 나갈 이유 | 궁금증 해소와 성취 |
| 탐험·수집 | 다음에도 돌아올 이유 | 나만의 장소 기록과 컬렉션 |
| 친구의 흔적 | 사람을 초대하고 장소에 애착을 갖는 이유 | 공유한 기억과 개인 메시지 |

### 한 번의 플레이 흐름

**시간·이동 조건 선택 → 사건 제안 → 수락 → 장소 이동 → 정지 후 단서 확인 → 추리 → 다음 장소 → 해결 → 발견 기록·수집품 → 편지 남기기**

세 요소를 별도 앱처럼 분리하지 않는다. 사건을 해결하는 동안 탐험이 기록되고, 결말에서 자연스럽게 흔적을 남기도록 연결한다.

### 반복 사용 흐름

첫 사건의 만족 → 근처 다른 사건 발견 → 지도에 개인 기록 축적 → 친구 초대 → 공동 사건과 편지 → 새로운 방문 동기

연속 출석 실패나 장거리 이동 강요로 반복 접속을 유도하지 않는다.

## 5. 첫 사건 콘셉트 — 《아직 도착하지 않은 편지》

### 기본 설정

- 장르: 따뜻한 동네 미스터리
- 목표 시간: 약 15분
- 조사 장소: 답사한 공공장소 3곳
- 플레이: 우선 1인, 후속 단계에서 2인 협동 변형
- 보상: 별 우표 1개, 첫 사건 기록, 장소 편지 작성 기회
- 고지: 실제 장소를 배경으로 한 허구이며 실제 주민·점포의 사건이 아님

> “임시 조사원님, 수취인을 찾지 못한 편지가 도착했습니다. 주소 대신 세 가지 표시가 그려져 있습니다.”

편지에 그려진 **나뭇잎·파도·별**의 의미를 찾아간다. 결말에서는 편지가 과거의 자신과 맺은 약속이라는 사실을 발견한다.

### 장면 구성

| 단계 | 경험 | 게임 기능 |
|---|---|---|
| 시작 | 사건 소개, 소요 시간·코스 확인, 수락 | 기대와 이동 조건 확인 |
| 장소 A | 세 기호의 뜻을 설명하는 일기 발견 | 단서 획득 및 첫 탐험 기록 |
| 장소 B | 서로 다른 시점의 엽서를 비교 | 단서 관계를 판단하는 추리 |
| 장소 C | 발신자·수신자 관계를 밝히는 마지막 기록 | 최종 선택 및 진상 공개 |
| 마무리 | 별 우표 획득, 자신 또는 친구에게 편지 | 수집과 소셜 연결 |

### 예시 대사

장소 A:

> “우리는 장소에 이름 대신 표시를 붙였다. 나뭇잎은 처음 만난 곳, 파도는 헤어진 곳, 별은 다시 만나기로 한 곳.”

장소 B에서는 기호의 순서가 다른 두 엽서를 비교한다. 날짜와 문맥을 근거로 차이를 해석하도록 설계한다.

장소 C의 결말:

> “언젠가 이 동네를 떠나더라도, 처음 좋아했던 것들을 잊지 말자.”

플레이어에게 이어지는 질문:

> “당신은 다음에 이곳에 오는 자신에게 무슨 말을 남기고 싶나요?”

### 퍼즐 설계의 미완성 부분

위 내용은 **감정선과 장면 구성 초안**이다. 현재 제시한 기호·날짜·대사만으로 정답이 유일하게 성립하는 완성 퍼즐은 아니다. 특히 ‘미래의 자신에게 보낸 편지’라는 결말을 뒷받침할 명시적 증거가 필요하다.

제작 전 다음을 확정한다.

1. 사건의 실제 시간 순서와 진상
2. 각 단서가 증명하는 사실과 공개되는 시점
3. 각 오답이 틀린 이유 및 이를 반박하는 증거
4. 정답에 필요한 모든 정보가 선택 이전에 제공되는지
5. 지역 배경지식이나 현장에 우연히 있는 사물에 의존하지 않는지
6. 세 단계 힌트: 볼 단서 안내 → 관계 설명 → 해설

첫 사건의 퍼즐은 작품 감상이 아니라 **획득한 증거로 풀 수 있는 문제**여야 한다. 오답으로 사건을 강제 종료하지 않는다.

## 6. 지도와 장소 설계

### 지도 정보의 역할

- 방문 후보인 공원·광장·공공 보행 공간 탐색
- 코스의 거리와 보행 경로 검토
- 방문 순서와 도착 판정
- 개인 탐험 기록의 위치 연결

지도 공급자의 기능·라이선스·요금·보행 정보 품질은 아직 비교하지 않았다. 실시간 경로 생성과 오프라인 지도는 MVP에 포함하지 않는다.

### 장소 선정 조건

- 합법적으로 접근 가능한 공공 공간
- 단서를 읽기 위해 안전하게 멈출 수 있는 장소
- 운영 시간과 출입 조건 확인
- 불필요한 도로 횡단과 계단 최소화
- 사유지·공사 구간·차도·민감한 시설을 목표 지점에서 제외
- 장소가 닫혔을 때 건너뛰거나 종료할 수 있는 동선

지도 데이터만으로 현장 접근성을 확정하지 않는다. 첫 코스는 답사 후 승인한다. 접근성 정보가 불확실하면 ‘확인되지 않음’으로 표시한다.

### 도착 판정

GPS는 정확한 물체 단위 위치가 아니라 **장소 주변에 도달했는지** 확인하는 용도로 사용한다.

- 도착 반경은 현장 측정 후 결정한다.
- 위치가 흔들릴 때 반경 밖으로 나갔다고 이미 얻은 단서를 취소하지 않는다.
- 도착 인식이 실패하면 ‘도착했어요’로 진행할 수 있게 한다.
- MVP는 위치 부정행위 방지보다 진행 안정성을 우선한다.
- 직선 방향 화살표만 믿고 장애물이나 차도를 가로지르게 하지 않는다.

### 코스 적응의 후속 방향

사건을 ‘공원 → 광장 → 휴식 가능한 공공장소’ 같은 장소 조건으로 정의해 다른 동네에 옮기는 방식을 연구한다. **이동 가능한 코스와 논리적으로 성립하는 사건을 각각 검증**해야 한다.

## 7. 탐험·수집 설계

탐험 지도는 ‘색칠한 면적’보다 **내가 알고 기억하는 장소**를 보여준다.

| 기록 | 표시 내용 |
|---|---|
| 첫 사건 해결 | 장소, 사건명, 해결 날짜 |
| 첫 공동 조사 | 함께한 친구, 공동 탐정 배지 |
| 편지를 남긴 장소 | 편지 존재 여부와 수신 대상 |
| 새로운 결말 발견 | 사건 추가 페이지 |

### 수집 원칙

- 아이템은 사건이나 장소의 이야기와 연결한다.
- 기본 보상은 해결 여부로 지급하고 속도 경쟁을 만들지 않는다.
- 더 멀리 걷는 것이 항상 더 좋은 보상으로 이어지지 않게 한다.
- 첫 버전에는 확률형 보상·거래·전투 능력치가 없다.
- 경험치와 레벨은 도입 여부를 후속 검증한다.

MVP 보상은 별 우표와 사건 기록 한 장으로 제한한다.

## 8. 친구와 함께하는 경험

### 협동 사건 — 후속 핵심 기능

같은 장소에 있는 두 사람에게 서로 다른 단서를 제공한다. 대화를 통해 맞춰야 진상을 알 수 있게 만든다.

예시:

- 조사원 A: 용의자의 시간 관련 진술
- 조사원 B: 해당 시계의 오차를 증명하는 기록
- 공동 목표: 실제 시간을 계산하고 다른 증거와 대조

이 예시는 협동 구조를 설명하기 위한 것이며 완성된 퍼즐은 아니다. 두 단서를 합치면 무엇을 확정할 수 있는지까지 설계해야 한다.

사람들을 다른 골목으로 흩어놓지 않아도 정보의 차이만으로 협동을 만들 수 있다. 연결이 끊기거나 친구가 나가면 단서를 통합해 혼자 계속할 수 있는 방식을 검토한다.

### 안경·휴대폰 혼합 참여

두 사람 모두 안경을 보유해야 하는 조건을 만들지 않는다.

- 안경 참여자: 현장 안내와 짧은 단서 확인
- 휴대폰 참여자: 증거 수첩과 기록 비교

역할 간 재미와 기여도를 균형 있게 설계한다. 휴대폰을 의도적으로 불편하게 만들어 안경의 장점을 부풀리지 않는다.

### 장소에 남기는 흔적

| 유형 | 열람 조건 | 사용 예 |
|---|---|---|
| 미래의 나에게 | 다시 방문했을 때 | 오늘의 다짐과 기억 |
| 친구에게 | 초대받은 사람이 현장에 도착했을 때 | 응원·추억·생일 메시지 |
| 다음 탐정에게 | 같은 사건의 정해진 구간에서 | 스포일러를 제한한 힌트 |

MVP는 **친구에게 보내는 짧은 텍스트 편지 하나**를 제공한다. 친구 관계망 전체를 구축하지 않고 초대 링크로 시작할 수 있다. 초대 링크의 전달·재공유와 열람 범위를 명확히 표시하고, 작성자가 철회할 수 있게 한다.

공개 자유 게시판, 실시간 친구 위치 공유, 사용자 제작 사건은 후속 범위다. 특히 공개 콘텐츠는 신고·차단·검수 체계를 준비한 뒤 검토한다.

## 9. 글래스 화면과 입력

### 화면 원칙

- 한 번에 하나의 목적: 이동, 단서 확인, 선택 중 하나
- 이동 중 긴 텍스트와 복잡한 조작 금지
- 안전하게 멈춘 뒤 단서 확인
- 음성은 짧게, 다시 듣기와 텍스트 대체 제공
- 실제 공간에 고정된 3D 캐릭터나 AR 물체를 전제로 하지 않음
- 밝은 환경에서 가독성, 한글 표시, 선택 상태를 실기기에서 확인

### 화면 목록

| 화면 | 핵심 내용 | 기본 행동 |
|---|---|---|
| 사건 제안 | 제목, 시간, 거리, 이동 조건 | 시작·취소 |
| 이동 | 다음 장소, 거리, 짧은 안내 | 일시정지 |
| 도착 | 조사 지점 도착 알림 | 단서 열기 |
| 단서 | 짧은 증거 한 장 | 다음·다시 보기 |
| 증거 수첩 | 획득한 단서 목록 | 선택·확인 |
| 추리 | 질문과 2~3개 선택지 | 선택·힌트 |
| 결과 | 선택 피드백과 해설 | 계속 |
| 해결 | 결말, 우표, 탐험 기록 | 마무리 |
| 편지 | 작성 안내와 수신 대상 | 휴대폰에서 작성 |

초기 시뮬레이터는 방향키·Enter 중심으로 검증한다. 음성 입력, 실제 기기의 뒤로 가기와 포커스 복원 등은 사용 가능한 API와 실기기 동작을 확인한 뒤 설계한다.

## 10. 콘텐츠 제작과 AI 역할

### 사람이 책임지는 부분

- 사건의 진상과 전체 시간 순서
- 단서 사이의 논리 관계
- 정답·오답·해설
- 장소 적합성과 이동 코스
- 결말의 감정선

### AI가 보조할 수 있는 부분

- 캐릭터 대사와 표현 변형
- 텍스트 길이 조절
- 검증된 증거에 근거한 단계별 힌트
- 접근성 설명과 음성 대본 초안

### 생성 제한

AI가 플레이 도중 범인, 날짜, 증거의 사실관계 또는 정답을 바꾸지 않는다. 실제 점포·주민에 대한 의혹이나 허구의 역사를 사실처럼 생성하지 않는다.

**첫 MVP는 고정 대본과 고정 힌트로 충분하다.** 생성형 AI 연동은 핵심 재미가 확인된 후 도입한다.

### 사건 데이터의 최소 구조

- 사건 ID, 버전, 제목, 소개, 허구 고지
- 장소 목록, 좌표, 접근 조건, 방문 순서
- 장면과 이동 조건
- 단서 ID, 내용, 공개 조건
- 질문, 선택지, 정답, 근거 단서, 오답 설명
- 단계별 힌트
- 결말, 보상, 후속 행동

콘텐츠 버전을 고정해 진행 중인 사건의 정답이 업데이트로 바뀌지 않게 한다.

## 11. 기술 접근과 검증 과제

### 현재 확인한 것

저장소의 `counter/`는 React·TypeScript·Vite 및 공식 UI Toolkit으로 만든 테스트 앱이다. 프로덕션 빌드와 웨일에 설치된 공식 Display Simulator 내 화면 표시를 확인했다. **비밀동네의 기능이나 실기기 연동이 구현된 것은 아니다.**

### 단계별 접근

| 단계 | 구성 | 검증할 것 |
|---|---|---|
| 시뮬레이터 프로토타입 | 웹앱, 고정 사건 데이터, 가상 위치 조작 | 글래스 화면과 전체 사건 흐름 |
| 스마트폰 현장 시험 | 실제 위치, 고정 코스, 진행 상태 저장 | 동선·도착 인식·퍼즐 재미 |
| 글래스 현장 시험 | 기기에서 지원하는 웹 또는 모바일 연동 경로 | 가독성·입력·오디오·위치·배터리 |
| 제한된 파일럿 | 초대와 편지 저장, 운영 도구 | 재사용과 콘텐츠 운영 비용 |

브라우저에서 지원되는 API와 글래스에서 실제 이용 가능한 기능은 다를 수 있다. 웹앱만으로 충분한지, 스마트폰 동반 앱과 Device Access Toolkit이 필요한지는 실기기 기술 검증 후 결정한다.

### 필수 확인 항목

- 위치 권한, 위치 정확도, 업데이트 주기
- 앱이 숨겨지거나 화면이 꺼질 때의 실행 동작
- 오디오 재생·중단·재개 조건
- 실제 입력과 포커스 이동
- 네트워크 단절과 진행 복구
- 한국어 렌더링과 음성 품질
- 지도 데이터 이용 조건과 캐싱 가능 범위
- 앱 배포·추가·공유 경로와 계정 조건

### 진행 상태

`제안 → 수락 → 이동 → 도착 → 조사 → 추리 → 다음 장소 → 해결 → 보상 → 종료`

어느 단계에서든 일시정지와 재개가 가능해야 한다. 보상은 재접속으로 중복 지급되지 않도록 처리한다. 위치 실패·연결 실패·닫힌 장소는 각각 대체 진행 또는 종료 안내를 제공한다.

## 12. MVP 범위

### 포함

- 실제 동네 한 곳과 답사한 코스 하나
- 약 15분짜리 완결된 사건 한 편
- 공공장소 세 곳
- 단서 비교 두 회와 최종 선택 한 회
- 증거 다시 보기 및 단계별 힌트
- 일시정지·재개와 진행 상태 저장
- 사건 완료 기록과 별 우표 한 개
- 초대받은 친구에게 전달하는 장소 편지 한 개
- 시뮬레이터용 가상 위치 이동 도구
- 스마트폰에서 확인 가능한 보조 화면

### 제외

- 전국 자동 코스 생성
- 자유 대화로 즉석 생성되는 사건
- 카메라 사물 인식과 현실 고정 3D 연출
- 실시간 다인 매칭과 경쟁 순위
- 공개 자유 게시판 및 사용자 제작 사건
- 친구의 실시간 위치 추적
- 확률형 아이템·거래·복잡한 성장 시스템
- 결제와 구독

2인 비대칭 단서 협동은 중요한 후속 기능이다. 첫 사건의 1인 완주 경험을 검증한 뒤 추가한다.

## 13. 개인정보와 현장 운영 원칙

- 정확한 이동 경로는 필요한 범위에서만 처리하고 서버 보관을 최소화한다.
- 탐험 기록은 기본적으로 개인에게만 보인다.
- 친구에게는 사용자가 명시적으로 공유한 편지와 결과만 제공한다.
- 위치 권한을 거부해도 사건 미리보기와 시뮬레이터 체험은 가능하게 한다.
- 카메라·상시 녹음은 첫 버전에 필요하지 않다.
- 공개 순위나 시간제한으로 달리기·위험한 횡단을 유도하지 않는다.
- 장소 운영자가 문제를 제기하거나 출입 조건이 바뀌면 해당 코스를 중지할 수 있어야 한다.

보관 기간·계정 체계·초대 인증 등 세부 정책은 실제 서비스 구조를 정할 때 명문화한다.

## 14. 검증 계획과 성공 기준

### 1단계: 사건 자체가 재미있는가

시뮬레이터와 스마트폰으로 소규모 시험을 한다. 5~8명 정도의 탐색적 테스트로 이해 오류와 진행 장애를 찾되, 이 규모를 시장성 검증으로 해석하지 않는다.

관찰할 질문:

- 별도 설명 없이 목표와 조작을 이해하는가?
- 장소 이동이 기대감을 만드는가, 지루한 대기처럼 느껴지는가?
- 단서를 근거로 답하는가, 무작위로 고르는가?
- 힌트는 막힌 부분을 풀어주는가?
- 결말을 자신의 말로 설명할 수 있는가?
- 다음 사건을 실제로 시작하거나 예약하는가?

### 2단계: 글래스가 더 나은가

스마트폰과 글래스로 난이도·거리·길이가 비슷한 서로 다른 사건을 체험하게 한다. 같은 사건의 정답을 이미 알아서 생기는 효과를 피하고, 체험 순서도 나눠 비교한다.

| 지표 | 확인하려는 것 |
|---|---|
| 완주와 중도 이탈 | 실제 경험의 지속 가능성 |
| 진행 오류·도움 요청 | 조작과 기술의 안정성 |
| 화면 확인을 위한 불필요한 정지 | 이동 경험의 부담 |
| 동행자와의 대화·주변 관찰 | 글래스가 주는 이점 |
| 다음 플레이 기기 선택 | 선언보다 구체적인 선호 |
| 가격 공개 후 대여·구매 의향 | 하드웨어 장벽 |

구매 의향 설문만으로 구매 전환을 단정하지 않는다. 가능한 경우 후속 체험 예약·대여 신청 등 실제 행동을 관찰한다.

### 판단 기준

- 재미는 있지만 글래스 선호가 약하면: 스마트폰 중심 게임으로도 가능성이 있는지 판단한다.
- 글래스가 좋지만 사건 재사용이 낮으면: 콘텐츠와 반복 동기를 개선한다.
- 두 가지 모두 긍정적이면: 협동 사건과 두 번째 동네로 확장한다.
- 기술 문제로 체험이 깨지면: 콘텐츠 평가와 기기·SDK 문제를 분리해 재검증한다.

숫자로 된 합격 기준은 첫 탐색 시험 후 정한다. 사후에 유리한 지표만 골라 성공을 주장하지 않는다.

## 15. 사업 모델 가설

초기 MVP는 과금하지 않고 재미와 재사용을 먼저 검증한다.

후속 후보:

1. 첫 사건 무료, 검증된 사건 묶음 유료 판매
2. 친구·연인에게 보내는 개인 모험 제작 기능
3. 지역 행사·문화시설과 함께 만드는 검수된 탐험 코스

구독은 지속적으로 공급할 콘텐츠와 반복 사용이 확인된 뒤 검토한다. 광고주가 경로를 왜곡하거나 사용자를 원치 않는 점포로 유도하는 구조는 피한다.

가격, 예상 매출, 시장 규모는 아직 산정하지 않았다.

## 16. 제작 순서와 단계별 완료 조건

### 단계 A — 사건과 코스 확정

- 첫 동네와 실제 장소 세 곳 선정·답사
- 전체 진상, 증거 관계, 정답·오답·힌트 작성
- 장소가 닫힌 경우의 처리 정의
- **완료 조건:** 종이 또는 화면으로 진행해도 사건을 논리적으로 끝까지 풀 수 있음

### 단계 B — 시뮬레이터에서 완주

- 사건 제안부터 편지 작성 안내까지 구현
- 가상 위치 전환과 진행 저장
- 방향키·선택·이전 화면 복귀 확인
- **완료 조건:** 개발자 설명 없이 처음부터 결말까지 진행 가능

### 단계 C — 실제 코스 시험

- 스마트폰 위치와 현장 동선 검증
- 거리·시간·접근성·단서 가독성 점검
- 퍼즐과 대사 수정
- **완료 조건:** 반복 시험에서 도착 오류로 진행이 막히지 않고 코스가 이용 가능함

### 단계 D — 글래스 비교 시험

- 지원 API 확인 및 필요한 연동 구현
- 실제 기기에서 입력·오디오·배터리·복구 검증
- 스마트폰 경험과 비교
- **완료 조건:** 재미와 기기 선호를 별도로 판단할 근거 확보

### 단계 E — 협동과 확장

- 같은 장소에서 다른 단서를 받는 2인 모드
- 초대·편지 열람·철회 기능 정비
- 두 번째 사건과 다른 장소 유형 추가
- **완료 조건:** 최초 사건 외에도 반복 사용이 발생하는지 확인

## 17. 다음에 결정할 질문

우선순위 순서:

1. 첫 코스를 만들 실제 동네는 어디인가?

3. 첫 현장 시험에 글래스 기기를 확보할 수 있는가?

5. 편지는 특정 친구에게 보낼 것인가, 초대 링크 소지자에게 열 것인가?
